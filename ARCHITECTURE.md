## 1. Project Vision

### What We Are Building

A **production-grade Agentic Knowledge Copilot** — a retrieval-augmented generation system
that ingests documents, indexes them with a hybrid retrieval pipeline, and answers questions
with grounded, cited answers. Every part is observable, evaluatable, and deployable.

This is not a tutorial chatbot. This is the shape of system companies like Glean, Notion AI,
and Onyx charge enterprise customers for. Here is what separates it from every tutorial:

| Dimension | Tutorial RAG | This Project |
|---|---|---|
| Ingestion | Load PDF → embed | Docling parse → semantic chunk → contextual enrichment → async index |
| Retrieval | Top-K cosine | BM25 + dense hybrid → RRF fusion → cross-encoder rerank |
| Generation | Stuff into prompt | Grounded answers with source citations, guardrails, streaming |
| Quality | Hope it works | RAGAS eval harness, 200-question golden set, CI gate |
| Observability | print() | OpenTelemetry traces, Langfuse dashboards, cost per query |
| Serving | Jupyter notebook | FastAPI async endpoints, SSE streaming, Docker Compose |
| Evaluation | None | RAGAS faithfulness ≥ 0.9, context precision ≥ 0.8, CI-gated |

### The Core Technical Bet: Anthropic Contextual Retrieval

The system is built around Anthropic's published Contextual Retrieval pattern:

- Every chunk is enriched with an 80–100 token LLM-generated "situational context blurb"
  before indexing in both the vector store and BM25 index
- Published result: **67% reduction in retrieval failure rate** (5.7% → 1.9%)
- Combined with hybrid BM25 + dense and cross-encoder reranking: highest-ROI stack in RAG
- The context blurb is generated by Groq Llama-3.3-70B (free API) using prompt caching
  pattern from Anthropic's cookbook

### Cost Philosophy

The LLM stack is cost-optimised without sacrificing quality:

| Component | Tool | Cost |
|---|---|---|
| Contextual enrichment (batch) | Groq Llama-3.3-70B | $0 (free API) |
| Embeddings | BGE-M3 (local CPU) | $0 |
| Reranking | BGE-reranker-v2-m3 (local CPU) | $0 |
| Answer generation | Claude Sonnet 4.6 + Citations API | ~$0.012/query |
| Answer generation (fallback) | Groq Llama-3.3-70B | $0 |
| All infrastructure | Self-hosted Docker | $0 |
| **Total monthly (200 queries)** | | **~$3/month** |

VESSL AI $47 credit is reserved exclusively for heavy batch ingestion jobs (>1,000 docs)
that would hit Groq's rate limits. It is NOT used for always-on serving.
(A10 GPU at $0.76/hr running 24/7 = $547/month — burns $47 in 2.5 days.)

## 2. Goals & Non-Goals

### Goals

- **G1**  Ingest PDFs, markdown, text files from local disk or URL
- **G2**  Index with Contextual Retrieval (context-enriched chunks via Groq)
- **G3**  Hybrid retrieval: BGE-M3 dense + BM25 sparse, fused with RRF at k=60
- **G4**  Cross-encoder reranking: BGE-reranker-v2-m3 (local CPU)
- **G5**  Answer generation: Claude Sonnet 4.6 with Citations API (primary) + Groq (fallback)
- **G6**  Agentic loop: if retrieval insufficient, LangGraph re-queries with rewritten query
- **G7**  Source citations on every answer (chunk reference + filename + page number)
- **G8**  RAGAS evaluation harness with 200-question golden dataset
- **G9**  CI gate: PR fails if faithfulness drops below 0.90 or context precision below 0.80
- **G10** Full OpenTelemetry tracing via self-hosted Langfuse (every query traced end-to-end)
- **G11** FastAPI backend with async endpoints, SSE streaming, Pydantic v2 schemas
- **G12** Docker Compose one-command startup for entire stack
- **G13** Redis semantic caching (skip LLM if semantically equivalent query was cached)
- **G14** Prometheus metrics + Grafana dashboard (latency, throughput, cost/query)

### Non-Goals (this version)

- **NG1** Multi-tenant ACL (Phase 2 — permission-aware retrieval)
- **NG2** Real-time streaming ingestion via Kafka (batch ingestion only)
- **NG3** Fine-tuning any model
- **NG4** Web scraping / live data sources (file and URL only)
- **NG5** Authentication / user management
- **NG6** GraphRAG / Neo4j (Phase 2)

### Two Core Pipelines

The system has two completely separate pipelines sharing only the storage layer:

```
INGESTION PIPELINE  (offline, async, runs once per document batch)
──────────────────────────────────────────────────────────────────
File/URL  →  Docling  →  SemanticChunker  →  ContextEnricher (Groq)
         →  BGE-M3 embed  →  Qdrant upsert
         →  BM25 index    →  Postgres metadata

QUERY PIPELINE  (online, sync, runs on every user question)
────────────────────────────────────────────────────────────────
User query  →  Redis cache check  →  Query rewriter (Groq)
           →  Hybrid retriever (BGE-M3 + BM25)  →  RRF fusion
           →  BGE reranker  →  LangGraph agent (reflect + retry)
           →  Claude Citations API  →  SSE stream  →  Response
```

## 4. Technology Stack & Why

### Model Choices

| Role | Model | Provider | Cost | Reason |
|---|---|---|---|---|
| Contextual chunking | `llama-3.3-70b-versatile` | Groq | $0 | Free API, fast, 70B quality for 80-token blurbs |
| Query rewriting / HyDE | `llama-3.3-70b-versatile` | Groq | $0 | Same model, free |
| Embeddings | `BAAI/bge-m3` | Local CPU | $0 | 111 languages, #1 hybrid search MTEB, Apache 2.0 |
| Reranking | `BAAI/bge-reranker-v2-m3` | Local CPU | $0 | Cross-encoder quality, 580MB, 200–400ms on CPU |
| Answer generation (default) | `llama-3.3-70b-versatile` | Groq | $0 | Free tier, [Source N] prompt citation, zero cost |
| Answer generation (demo/citation) | `LongCite-llama3.1-8b` | VESSL A10 | ~$0.76/hr (on-demand) | Fine-tuned for native sentence-level citations, MIT license, 128K ctx |
| RAGAS eval judge | `llama-3.3-70b-versatile` | Groq | $0 | Free tier, RAGAS custom LLM adapter, sufficient quality |

**Why BGE-M3 over Voyage-3-large:**
BGE-M3 is within 2.5% NDCG of Voyage-3-large (0.545 vs 0.568 on BEIR) but costs $0 vs $0.18/MTok.
BGE-M3 is ranked #1 on hybrid search — exactly our use case. Apache 2.0, local inference, no vendor.

**Why Groq free tier as default generator:**
Groq free tier = 14,400 tokens/min, zero cost, no credit card. Llama-3.3-70B follows structured
JSON output reliably with [Source N] citation prompting. Sufficient for all development and demo
traffic. VESSL $47 is reserved for batch ingestion overflow and LongCite demo sessions.

**Why LongCite-8B over Claude Citations API for the citation demo path:**
THUDM/LongCite-llama3.1-8b (MIT license, HuggingFace) is fine-tuned specifically to produce
sentence-level citations natively — the citation behaviour is baked into model weights, not
prompted. This is architecturally equivalent to what Claude's Citations API does server-side.
128K context window. Runs on VESSL A10 (24GB VRAM). Cost: ~$1.52 per 2-hour demo session,
not always-on. This approach removes the hard dependency on any paid API while keeping the
portfolio story: "we use a fine-tuned open-source model that generates verified source citations."

### Infrastructure Choices

| Component | Tool | Why |
|---|---|---|
| Vector DB | Qdrant (self-hosted) | Best filtered search (ACORN HNSW), namespacing, Rust-fast, free self-host |
| Keyword search | rank-bm25 | Pure Python, zero deps, sufficient for in-memory BM25 |
| Metadata store | PostgreSQL 16 | ACID, relational, stores doc metadata + eval results + golden set |
| Cache | Redis 7 | Semantic caching by embedding proximity, TTL-based query dedup |
| Orchestration | LangGraph 0.2+ | Stateful graph, checkpointing, HITL-ready, Langfuse native |
| API framework | FastAPI 0.115+ | Async-native, Pydantic v2, SSE streaming, auto OpenAPI docs |
| Document parsing | Docling (IBM) | MIT license, ~94% table accuracy, handles multi-column PDFs |
| Observability | Langfuse self-hosted | MIT license, $0, OTel native, full trace per query |
| Evaluation | RAGAS + DeepEval | RAGAS for RAG metrics, DeepEval for CI assertions |
| Containers | Docker Compose | One-command `docker compose up` starts entire stack |
| CI/CD | GitHub Actions | RAGAS eval on PR, fail if faithfulness drops more than 5% |

### Why NOT These Tools

| Tool | Reason rejected |
|---|---|
| LangChain (chains) | Replaced by LangGraph (same ecosystem, stateful graphs, better for agents) |
| Pinecone | $50/month minimum, vendor lock-in; Qdrant self-hosted is equivalent quality |
| OpenAI embeddings | $0.13/MTok vs BGE-M3 at $0 — no quality advantage justifies cost |
| Chroma | Not production-ready, no filtering, no namespacing |
| FAISS | In-memory only, no persistence, no filtering |
| Weaviate | Higher operational overhead than Qdrant for same use case |
| VESSL for serving | $0.76/hr × 24h = $18.24/day — $47 lasts 2.5 days. Wrong use of credits. |

```
│          GPU (VESSL, bulk jobs)    │
│  Cost: $0                          │
└──────────┬──────────────┬──────────┘
           │              │
           ▼              ▼

                      │
```

### Contextual Enrichment Prompt

```python
CONTEXT_SYSTEM = "You are a document understanding assistant."

CONTEXT_USER = """<document>
{full_document_text}
</document>

Here is the chunk we want to situate within the document:
<chunk>
{chunk_text}
</chunk>

Write a short context (80-100 tokens) explaining where this chunk sits in the document,
what broader section or topic it belongs to, and what surrounding context is relevant to
understanding it. Do not summarize the chunk itself. Output only the context, no preamble.
"""
```

This is the Anthropic Contextual Retrieval cookbook pattern. The full document is passed
once and the LLM responds with a context blurb for each chunk individually. Cost is
dominated by the output tokens (80 tokens × chunk count).

## 6. Pipeline 2 — Query

### Step-by-Step Flow

```
User Query: "What are the main revenue drivers in Q3?"
         │
         ▼
┌────────────────────────────────────┐
│  STEP 0: REDIS CACHE CHECK         │
│                                    │
│  1. Embed query with BGE-M3        │
│  2. Search Redis for cached query  │
│     with cosine similarity ≥ 0.95  │
│  HIT  → return cached response     │
│         latency: < 50ms            │
│  MISS → continue to Step 1         │
│  TTL: 1 hour                       │
└──────────────────┬─────────────────┘
                   │ (cache miss)
                   ▼
┌────────────────────────────────────┐
│  STEP 1: QUERY REWRITER            │
│  (LangGraph Node: query_rewriter)  │
│                                    │
│  Classify query type:              │
│  - FACTUAL  → use as-is            │
│  - SPARSE   → HyDE expansion:      │
│    generate hypothetical answer    │
│    and embed that instead          │
│  - COMPLEX  → decompose into       │
│    3 sub-queries for multi-query   │
│    retrieval                       │
│                                    │
│  Model: Groq llama-3.3-70b         │
│  Cost: $0                          │
└──────────────────┬─────────────────┘
                   │
                   ▼
┌────────────────────────────────────┐
│  STEP 2: HYBRID RETRIEVAL          │
│  (runs both branches in parallel)  │
│                                    │
│  Branch A — DENSE:                 │
│  - Embed query with BGE-M3         │
│  - Qdrant cosine search top-50     │
│  - Returns: [(chunk, score), ...]  │
│                                    │
│  Branch B — SPARSE:                │
│  - Tokenize query                  │
│  - BM25 search top-50              │
│  - Returns: [(chunk, score), ...]  │
│                                    │
│  Fusion: RRF at k=60               │
│  Formula per chunk: Σ 1/(k+rank)   │
│  (summed across both ranked lists) │
│  Final: top-50 merged candidates   │
└──────────────────┬─────────────────┘
                   │
                   ▼
┌────────────────────────────────────┐
│  STEP 3: CROSS-ENCODER RERANK      │
│                                    │
│  Model: BAAI/bge-reranker-v2-m3    │
│  Input: (query, chunk) pairs × 50  │
│  Scores each pair jointly          │
│  Output: top-5 chunks              │
│  Latency: ~300ms on CPU            │
│  Cost: $0                          │
└──────────────────┬─────────────────┘
                   │
                   ▼
┌────────────────────────────────────┐
│  STEP 4: LANGGRAPH AGENT LOOP      │
│                                    │
│  State: RAGState {                 │
│    query, rewritten_queries,       │
│    retrieved_chunks,               │
│    retrieval_attempt (max 2),      │
│    is_sufficient                   │
│  }                                 │
│                                    │
│  Node A: CHECK SUFFICIENCY         │
│  - Estimate context_recall:        │
│    do top-5 chunks cover the query?│
│  - SUFFICIENT   → Node C (generate)│
│  - INSUFFICIENT → Node B (retry)  │
│    if attempt < 2                  │
│  - INSUFFICIENT → Node C anyway   │
│    if attempt >= 2 (hard cap)      │
│                                    │
│  Node B: QUERY REWRITE + RETRY     │
│  - Identify gap: what is missing?  │
│  - Generate new search query       │
│  - Re-run steps 2 + 3              │
│  - Merge new chunks with existing  │
│  - Re-run sufficiency check        │
│                                    │
│  Node C: PROCEED TO GENERATION     │
└──────────────────┬─────────────────┘
                   │
                   ▼
┌────────────────────────────────────┐
│  STEP 5: ANSWER GENERATION         │
│                                    │
│  DEFAULT: Groq llama-3.3-70b       │
│  - [Source N] prompt citation:     │
│    "Cite every claim as [Source N] │
│     where N matches the provided   │
│     context blocks. Return JSON:   │
│     {answer, citations:[{source,   │
│     cited_text, chunk_id}]}"       │
│  - Post-process JSON → Citation    │
│    objects with chunk references   │
│  - Cost: $0 (Groq free tier)       │
│                                    │
│  DEMO PATH: LongCite-llama3.1-8b   │
│  - Fine-tuned for native sentence- │
│    level citations (THUDM, MIT)    │
│  - Citations baked into weights,   │
│    not prompted                    │
│  - Hosted on VESSL A10 on-demand   │
│  - Spin up for interview demos     │
│  - Cost: ~$1.52 per 2hr session    │
│                                    │
│  Context assembly (both paths):    │
│  [Source 1]\n{chunk_1_text}\n      │
│  [Source 2]\n{chunk_2_text}\n ...  │
└──────────────────┬─────────────────┘
                   │
                   ▼
┌────────────────────────────────────┐
│  STEP 6: SSE STREAM + CACHE WRITE  │
│                                    │
│  - Tokens streamed via SSE         │
│  - Citations appended at end       │
│  - Langfuse trace span closed      │
│  - Result written to Redis cache   │
│  - Prometheus counters incremented │
│  - query_id returned in response   │
└────────────────────────────────────┘
```

### LangGraph State Definition

```python
from typing import TypedDict

class RAGState(TypedDict):
    query: str
    rewritten_queries: list[str]
    retrieved_chunks: list[dict]
    retrieval_attempt: int          # max 2 retries
    is_sufficient: bool
    answer: str
    citations: list[dict]
    trace_id: str

# Graph definition
START → query_rewriter_node
query_rewriter_node → hybrid_retriever_node
hybrid_retriever_node → reranker_node
reranker_node → sufficiency_checker_node
sufficiency_checker_node → generate_node          (if sufficient OR attempt >= 2)
sufficiency_checker_node → query_rewriter_node    (if not sufficient AND attempt < 2)
generate_node → END
```

```sql
-- One row per ingested source file
CREATE TABLE documents (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),

CREATE TABLE chunks (

    char_start  INTEGER,

CREATE TABLE eval_runs (
    id                 UUID PRIMARY KEY DEFAULT gen_random_uuid(),

    context_precision  FLOAT,

    answer_relevancy   FLOAT,
    latency_p50_ms     FLOAT,
```

## 10. Evaluation Strategy

### RAGAS Metric Targets

| Metric | Definition | Minimum (ship) | Target (portfolio) | Excellent (interview) |
|---|---|---|---|---|
| **Faithfulness** | Claims supported by retrieved chunks | 0.85 | **0.90** | 0.93+ |
| **Context Precision** | Retrieved chunks ranked correctly | 0.75 | **0.80** | 0.85+ |
| **Context Recall** | All relevant info retrieved | 0.70 | **0.75** | 0.80+ |
| **Answer Relevancy** | Answer relevant to question | 0.80 | **0.85** | 0.90+ |

### Golden Dataset Composition (200 questions)

| Category | Count | Description |
|---|---|---|
| Factual | 60 | Specific numbers, names, dates |
| Analytical | 60 | Trends, comparisons, implications |
| Multi-hop | 50 | Require combining 2+ chunks |
| Adversarial | 30 | Answer NOT in docs — must respond gracefully |

### CI/CD Eval Gate

```yaml
# .github/workflows/eval.yml
- name: Run RAGAS evaluation
  run: python evaluation/runner.py --commit $GITHUB_SHA --output eval_results.json

- name: Enforce quality gate
  run: |
    python -c "
    import json, sys
    r = json.load(open('eval_results.json'))
    failures = []
    if r['faithfulness'] < 0.90:
        failures.append(f'faithfulness {r[\"faithfulness\"]:.3f} < 0.90')
    if r['context_precision'] < 0.80:
        failures.append(f'context_precision {r[\"context_precision\"]:.3f} < 0.80')
    if failures:
        print('EVAL FAILED:', failures)
        sys.exit(1)
    print('Eval passed:', r)
    "
```

### Expected Baseline Progression

| Pipeline Stage | Expected Context Precision |
|---|---|
| Dense-only (baseline to measure first) | ~0.61 |
| + BM25 hybrid with RRF | ~0.72 |
| + Cross-encoder rerank | ~0.80 |
| + Contextual Retrieval (Groq context blurbs) | ~0.88 |

These improvements follow Anthropic's published benchmarks and Kanaeru production case study.
Measure your own baseline on your actual corpus — do not assume these numbers.

### Failure Mode Diagnosis

```
faithfulness low + context_recall high  →  generator hallucinating despite good context
context_recall low + faithfulness OK    →  retriever missing relevant chunks
context_precision low                   →  reranker not scoring correctly
answer_relevancy low                    →  query rewriting or generation prompt issue
all metrics OK + wrong answer           →  context drift (silent failure) — add adversarial set
```

## 15. Architecture Decision Records

### ADR-001: BGE-M3 over Voyage-3-large

**Decision:** BGE-M3 for all embeddings.

**Why:** 2.5% NDCG gap (0.545 vs 0.568 BEIR) does not justify $0.18/MTok at portfolio scale.
BGE-M3 is #1 on hybrid search (our exact use case), Apache 2.0, local inference, no API key.

**Trade-off accepted:** Must download 2.3GB model on first run. Slightly slower cold start.
Cannot use Voyage domain-specific variants (code, finance) without swapping.

---

### ADR-002: Groq free tier as default generator, VESSL only for demos and batch ingestion

**Decision:** Groq Llama-3.3-70B for all runtime LLM calls. VESSL only for batch ingestion
overflow and on-demand LongCite demo sessions.

**Why:** VESSL A10 at $0.76/hr × 24 = $18.24/day. $47 credit lasts 2.5 days as always-on.
Groq free tier provides Llama-3.3-70B at 14,400 tokens/min — sufficient for all development,
evaluation, and demo traffic at portfolio scale. Total recurring cost = $0.

**Trade-off accepted:** Rate limited on Groq at high volume (14,400 tok/min).
For generation at this scale (~200 queries/month) that limit is never reached.
For batch ingestion > 500 docs, spin up VESSL.

---

### ADR-003: LangGraph over raw Python for agent orchestration

**Decision:** LangGraph for the query agent loop.

**Why:** Stateful graph, checkpointing, native Langfuse/LangSmith integration, HITL-ready.
Kakao Service Desk Agent (real Korean production case) uses LangGraph + Qdrant — direct match.

**Trade-off accepted:** ~50ms overhead per query vs raw Python. More boilerplate.
Worth it for the skills learned and the portfolio story.

---

### ADR-004: LongCite-8B (VESSL, on-demand) + Groq over Claude Citations API

**Decision:** Groq Llama-3.3-70B as primary generator with structured [Source N] citation
prompting. LongCite-llama3.1-8b on VESSL A10 as an on-demand demo path for native citations.

**Why:** Claude's Citations API costs ~$0.012/query and requires a paid Anthropic account.
LongCite-8B (THUDM, MIT license) is a fine-tuned Llama 3.1 model that generates sentence-level
citations natively — the citation behaviour is in the weights, not prompted. It is architecturally
equivalent to what Claude does server-side. Runs on VESSL A10 (24GB VRAM). Cost: ~$1.52 per
2-hour on-demand demo session — not always-on.

For routine queries (development, CI, daily demos), Groq with [Source N] JSON prompting produces
citation objects that map cleanly to chunk references. This is already the pattern Anthropic's
own cookbook describes for models without native Citations API support.

**Trade-off accepted:** LongCite requires spinning up VESSL manually for demo sessions.
Groq citations are prompt-engineered, not weight-level — edge cases may need post-processing.
Mitigated by the `rag-citation` library as an optional verification layer (SpaCy + SentenceTransformers,
zero API cost) that validates claim-to-source mapping after generation.

---

### ADR-005: Self-hosted Langfuse over LangSmith Cloud

**Decision:** Langfuse self-hosted on Docker Compose.

**Why:** MIT license, $0, Postgres + ClickHouse stack, OpenTelemetry native, framework-agnostic.
LangSmith is $39/month for production tier. Interview story: "I run full LLMOps on my own infra."

**Trade-off accepted:** Self-hosting means we manage it. Docker Compose adds 3 services.
Postgres storage requires disk management on deployment.

| Cost per query? | $0 — Groq free tier for generation, BGE local for embeddings + reranking, Groq for RAGAS eval judge. LongCite demo path costs ~$1.52 for a 2-hour VESSL session. |

## 18. Glossary

| Term | Definition |
|---|---|
| **BM25** | Best Match 25 — keyword sparse retrieval, strong for exact terms, IDs, rare tokens |
| **Chunk** | Document segment of 256–512 tokens with overlap — basic unit of retrieval |
| **LongCite** | Fine-tuned open-source model (THUDM/MIT) that generates sentence-level citations natively — citation behaviour is baked into model weights, not prompted. Closest open-source equivalent to Anthropic's Citations API. |
| **Contextual Retrieval** | Prepend LLM-generated context blurb to each chunk before embedding |
| **Context Precision** | RAGAS: were retrieved chunks ranked correctly? |
| **Context Recall** | RAGAS: did retrieval surface all relevant information? |
| **Cross-encoder** | Reranker that jointly encodes (query, doc) pairs — more accurate than bi-encoder |
| **Dense retrieval** | Embedding-based semantic search using cosine / dot-product similarity |
| **Faithfulness** | RAGAS: fraction of answer claims supported by retrieved chunks |
| **HyDE** | Hypothetical Document Embeddings — embed a generated answer as a richer query |
| **LangGraph** | LangChain's stateful agent graph framework — nodes + edges + state |
| **PTI** | Parse-Transform-Index — unstructured data ingestion pipeline (analog of ETL) |
| **RAG** | Retrieval-Augmented Generation — retrieve relevant context, then generate answer |
| **RAGAS** | RAG evaluation framework: faithfulness, precision, recall, answer relevancy |
| **RRF** | Reciprocal Rank Fusion — merge ranked lists: score = Σ 1/(k+rank), k=60 |
| **Semantic caching** | Cache Q→A by embedding proximity — skip LLM for near-duplicate queries |
| **Sparse retrieval** | Keyword-based retrieval (BM25) — operates on term frequencies |
| **OTel** | OpenTelemetry — observability standard for distributed traces + metrics |
| **VESSL** | Korean GPU cloud — used for batch ingestion only ($47 credit = ~61 A10 hours) |
